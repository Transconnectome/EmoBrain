## 핵심 결과 요약

**0단계**
- 34개 범주는 고차원(분산 80%에 주성분 19개)이고 0점 영상이 대부분이며, 범주마다 자료량과 라벨 신뢰도 추정이 크게 다르다(0.28~0.96).
- 검사한 요인 중 라벨과 얽힌 것은 영상 길이뿐이다(surprise +0.24 등). run 안 순서, 세션, 블록 머리 움직임(FD·DVARS)은 라벨과 순위 상관이 보이지 않았다. 검사 범위 안의 기술이며, 이 요인들이 뇌 예측에 기여하지 않는다는 뜻은 아니다. 저수준 시각 특징은 대부분 라벨에서 1% 안팎을 설명한다.
- 점검한 항목(결측, 튀는 블록·run, 같은 영상 반응의 안정성)에서 뇌 자료 문제는 발견되지 않았다. 같은 영상에 대한 반응은 시각·배측 주의 영역에서 안정적이고, Limbic·피질하·시상하부에서는 거의 재현되지 않는다.

**1단계** (Horikawa 5명, 469개 영역 평균, 피험자별 모델, 분할 `horikawa_rungroup6_v1`)

| 비교 | A34 (34개 평균 r, 괄호 = 27개 기술 요약) | A14 (평균 r) |
|---|---|---|
| 뇌 단독 | 0.33 (0.37) | 0.36 |
| 저수준 시각 / 영상 길이 / 뇌 전체 신호 | 0.14 / 0.02 / 0.03 (0.16 / 0.03 / 0.04) | 0.15 / 0.00 / 0.03 |
| 내용만: 의미 73 / 시각 1000 (영상 단위, 아래 주의) | 0.55 / 0.37 (0.61 / 0.41) | 0.60 / 0.36 |
| 뇌 → 의미 73 → 정서 | 0.31 (0.35) | 0.36 |
| 뇌 + 의미 73 | 0.53 (0.59) | 0.58 |

- 주의: "내용만" 행은 영상 단위 분석(평가 영상 2,181개)이고, 뇌를 쓰는 행은 피험자별 뇌 QC 통과 행(A34 2,070~2,180개)이다. 학습·평가 영상이 달라 두 행의 차이를 뇌 입력 추가의 효과로 읽지 않는다. 같은 행 비교는 `content_ladder.py --sub` 의 내용만 조건으로 다시 계산한다 (재실행 대기).
- 27개 요약은 결과를 본 뒤 제안한 기술 요약이다(`decisions_proposed.md`). 34개 결과를 함께 보존한다.
- 뇌 단독 예측은 48개 차원 모두에서 5명 전원 r 가 양수다. 유의성 검정은 하지 않았다. sub-05 guilt 는 r 가 양수지만 오차 감소율은 음수(-0.0015)라 r 와 오차를 함께 본다. 길이·뇌 전체 신호 기준선은 거의 0 이다.
- 뇌에서 예측한 의미 73 을 거친 정서 예측이 뇌 직접 예측과 비슷한 r 를 보였다 (A34 34개 0.314 대 0.329 로 약 95%, 27개 0.348 대 0.375 로 약 93%, A14 약 99%). r 의 비율이며 공유 정보, 설명 분산, 신경 경로의 비율이 아니다. 이 경로의 정서 모델은 학습 영상의 실제 의미 특징(사람 annotation)과 라벨로 학습하고, 평가 영상에서만 뇌 예측 특징을 넣는다.
- 학습 곡선: 학습 영상 609개에서 전체 대비 84%, 924개에서 91%, 1,215개에서 95%(영상당 스캔 약 13.2초). 이 입력과 이 5명의 학습 영상 수를 줄인 결과이며, 새 촬영의 영상 수나 평정자 수를 정한 결과가 아니다.

## 상태와 한계

- 결과 보고 수준이다. 다른 서버·다른 AI 가 재검산하지 않았다.
- **분할 `horikawa_rungroup6_v1` 은 이번 분석용이며, 사용자 계획에 따라 분할은 다시 만들 예정이다.** 기존 무작위 분할 파일(`project/shared/data/horikawa_5fold.csv`, `horikawa_split.csv`)은 61개 run 모두에 fold 가 섞여 뇌 모델에 쓰지 않았다. 그 파일들은 이 브랜치에서 건드리지 않았다.
- 입력이 469개 영역 평균이다. voxel 패턴, ROI 단독(편도체·시각 피질), 비선형 모델은 아직 보지 않았다.
- 의미 73 은 사람(평정자 12명) annotation 이라 순수한 자극 정보가 아니다. V-JEPA·caption 문장 표현으로의 재확인이 필요하다.
- 뇌 + 내용은 이어 붙인 입력에 규제 강도 하나를 썼다. 의미 73 단독보다 좋아지지 않은 것은 이 결합 방식과 서로 다른 영상 집합에서 나온 결과라, 뇌 정보의 부재를 뜻하지 않는다. 입력 묶음별 규제(banded ridge)로 다시 볼 예정이다.

## 2026-10-26 검토 반영 (Perlmutter)

외부 검토(커밋 1741cb7 대상)의 지적을 코드와 문구에 반영했다. 랩서버 재실행 전이므로 위 수치는 그대로다.
- 같은 행 비교: `content_ladder.py --sub` 에 내용만(특징 이름)과 뇌만(`brain_roi469`) 조건을 같은 피험자 행·fold 로 추가했고, `--summarize` 가 `ladder_same_rows_*.tsv` 를 만든다. 그림의 사다리도 이 같은 행 결과로 그린다.
- 학습 곡선 fallback: 안쪽 묶음이 하나뿐일 때 행 번호 홀짝으로 나누던 것을 run 을 쪼개지 않는 분할로 바꾸고 발동 횟수를 `lc_run_info_sub-XX.json` 에 기록한다. 업로드된 실행의 run 선택을 저장소의 분할표와 v3_qc 행으로 재구성해 보면 1,440개 fit 중 발동 0회였고, 행 수(2,177/2,180/2,172/2,160/2,070)가 업로드 결과와 같다. 따라서 기존 곡선은 이 수정의 영향을 받지 않는다.
- 학습 곡선 오차 기준: 기존 `error_reduction` 은 모든 학습량에서 바깥 학습 fold 전체의 평균을 기준으로 한다. 그 학습량의 학습 영상 평균을 기준으로 한 `error_reduction_subset_mean` 을 추가했다. Pearson r 곡선은 영향이 없다.
- 수렴 기록: soft BCE 의 L-BFGS 결과(성공 여부, 반복 수, 종료 코드)를 run_info 의 `softbce_convergence` 에 기록한다. 선택된 규제 강도가 격자 끝에 걸린 비율은 `brain_baseline.py --summarize` 가 `selected_lambda_edges.tsv` 로 낸다. 기존 실행의 수렴과 격자 끝 선택은 랩서버 산출물로 확인해야 한다.
- 27개 요약: 제안 상태로 표기하고 34개 결과를 앞에 둔다. Horikawa 2020 의 decoding·encoding 은 34개 범주와 14개 척도로 했고, 27개는 결과 서술, UMAP 색 지정, 군집 수에 쓰였다.

## T004 와의 관계

원격의 T004(Perlmutter Claude Code, `project/baseline/brain_decoding/`)는 Horikawa sub-01 의 소규모 개발 부분집합(fit 8 / tune 2 / evaluate 2 run, voxel dual ridge)으로 loader·split·scaling 을 점검하는 pilot 이다. 이 폴더의 1단계는 5명 전체, 469개 영역 평균, run 묶음 6겹 교차검증의 기준선으로, 목적과 범위가 다르다. 둘을 대체 관계로 보지 않으며, 분할과 입력을 맞출지는 분할을 다시 정할 때 함께 결정한다.
